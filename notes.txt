# AZURE DATA ENGINEERING — DAY 01
## Module 01: Data Engineering Fundamentals

### 1. What is Data?
Data is a collection of raw facts, values, observations, and records that can be processed into meaningful information.

Example: Customer ID, product name, order amount, transaction date.

### 2. What is Data Engineering?
Data Engineering is the practice of designing, building, testing, and maintaining systems that collect, store, process, and deliver reliable data for analytics and business operations.

### 3. Why Do Companies Need Data Engineers?
- Data is generated across many systems.
- Source data can be incomplete, inconsistent, or duplicated.
- Businesses require accurate and timely analytics.
- Data pipelines must run automatically and reliably.
- Failed jobs must be investigated and recovered.
- Sensitive data must be protected.

### 4. End-to-End Data Engineering Workflow
1. Identify source systems.
2. Extract or ingest source data.
3. Store data securely.
4. Validate and transform data.
5. Prepare analytics-ready datasets.
6. Schedule and orchestrate pipelines.
7. Monitor executions and data quality.
8. Troubleshoot failures and maintain pipelines.

### 5. Major Azure Technologies
- Azure Data Factory: Data ingestion, orchestration, and scheduling.
- Azure Data Lake Storage Gen2: Cloud-based data storage.
- Azure SQL Database: Relational database service.
- Azure Databricks: Data processing and analytics platform.
- PySpark: Python interface for distributed Apache Spark processing.
- Delta Lake: Transactional storage layer for lakehouse tables.

### 6. ETL and ELT
ETL = Extract, Transform, Load.
ELT = Extract, Load, Transform.

ETL transforms data before loading it into the target.
ELT loads data into the target processing environment before transforming it.

### 7. Types of Data
Structured Data: Data organized using a defined schema, such as relational tables.

Semi-Structured Data: Data with identifiable keys or tags but flexible structure, such as JSON and XML.

Unstructured Data: Data without a natural predefined tabular structure, such as images, audio, and video.

### 8. Database Fundamentals
Database: Organized collection of data.
Table: Related data organized into rows and columns.
Row: A single record.
Column: A specific attribute.
Schema: Definition of table structure, data types, and constraints.
Primary Key: A column or combination of columns uniquely identifying each row.

SQL example:

    CREATE TABLE customers (
        customer_id INT PRIMARY KEY,
        name VARCHAR(100),
        city VARCHAR(100)
    );

### 9. Data Quality
Data quality includes accuracy, completeness, validity, consistency, uniqueness, and timeliness.

When suspicious records appear:
1. Verify business rules.
2. Investigate the source.
3. Validate against defined requirements.
4. Preserve and flag/quarantine confirmed invalid records.
5. Correct issues using approved logic.
6. Reprocess and verify results.

### 10. Real Company Scenario
A retail company receives customer, order, payment, and refund data.

A data engineer builds reliable pipelines that ingest source data, preserve raw records, validate data, apply business transformations, and deliver trusted datasets.

### 11. Interview Questions and Answers

Q1: What is Data Engineering?
A: Building and maintaining reliable systems for collecting, storing, transforming, and delivering data.

Q2: What is a data pipeline?
A: An automated sequence of steps for moving and processing data.

Q3: What is ETL vs ELT?
A: ETL transforms before loading; ELT loads before transforming.

Q4: What is structured data?
A: Data organized using a defined schema, commonly relational tables.

Q5: Is JSON structured or semi-structured?
A: JSON is generally semi-structured because it supports flexible and nested fields.

Q6: What is a primary key?
A: A relational database constraint that uniquely identifies each row and disallows NULL key values.

Q7: What should a data engineer do with duplicate records?
A: Verify business rules and source semantics before implementing deduplication.

## SQL Fundamentals — INSERT INTO

### 1. Definition
`INSERT INTO` is a SQL Data Manipulation Language (DML) statement used to add new records to an existing table.

### 2. Meaning
INSERT INTO stores new data in a relational database table.

### 3. Syntax

```sql
INSERT INTO table_name (column1, column2)
VALUES (value1, value2);
```

### 4. Important SQL Keywords
- `INSERT INTO`: Specifies the destination table.
- Column list: Identifies target columns.
- `VALUES`: Provides the new record values.
- `GO`: Executes the SQL batch in sqlcmd.

### 5. Why Use INSERT?
To store new customers, products, orders, and transactions in database tables.

### 6. Real Data Engineering Use
Data engineers may insert validated records into staging, reference, or analytical tables. Production pipelines also use controlled bulk loading and other ingestion approaches.

### 7. Example

```sql
INSERT INTO dbo.customers
    (customer_id, customer_name, city)
VALUES
    (101, N'Ravi', N'Hyderabad');
GO
```

### 8. Difference and Cautions
- `CREATE TABLE`: Creates a table structure.
- `INSERT INTO`: Adds records to an existing table.
- `SELECT`: Retrieves data from a table.
- Duplicate primary key values are rejected when a primary key constraint exists.
- Required NOT NULL columns must contain valid values unless defaults or generated values apply.
- `N'...'` represents a Unicode string literal in SQL Server.
- Repeating the same INSERT may create duplicates or a primary key violation.

### 9. Interview Q&A

**Q1: What is INSERT INTO?**
A: A DML statement that adds new rows to a table.

**Q2: Can INSERT insert multiple rows?**
A: Yes, a single INSERT statement can insert multiple rows.

**Q3: What happens if a duplicate primary key is inserted?**
A: SQL Server rejects the operation when the primary key constraint is enforced.

**Q4: What is the difference between DDL and DML?**
A: DDL defines database structures, while DML operates on data inside those structures.

## SQL Fundamentals — Multiple Row INSERT

### 1. Definition
A multi-row INSERT statement inserts multiple records into a database table using one SQL statement.

### 2. Meaning
Instead of inserting each record individually, multiple rows can be added together.

### 3. Syntax

```sql
INSERT INTO table_name (column1, column2)
VALUES
    (value1, value2),
    (value3, value4);
```

### 4. Important Keywords
- INSERT INTO: Specifies the target table.
- VALUES: Defines the data to insert.
- Comma: Separates multiple rows.
- GO: Executes the SQL batch in sqlcmd.

### 5. Why Use It?
To efficiently add multiple records with fewer SQL statements.

### 6. Real Data Engineering Use
Data engineers load validated records into staging, reference, and analytical tables. Large production datasets usually require bulk loading or automated ingestion pipelines.

### 7. Example

```sql
INSERT INTO dbo.customers
    (customer_id, customer_name, city)
VALUES
    (102, N'SAI', N'VIJAYAWADA'),
    (103, N'KIRAN', N'GUNTUR'),
    (104, N'PRIYA', N'HYDERABAD');
GO
```

### 8. Differences and Cautions
- Single-row INSERT adds one record.
- Multi-row INSERT adds multiple records using one statement.
- Primary key values must remain unique.
- SQL Server supports up to 1,000 rows in a direct INSERT ... VALUES statement.
- In production, use appropriate bulk-loading approaches for larger datasets.
- Verify existing records before rerunning an INSERT to avoid duplicates or primary key errors.

### 9. Interview Q&A

Q: Can INSERT INTO insert multiple records?

A: Yes. Multiple row-value expressions can be specified in one INSERT statement.

Q: What happens if one inserted value violates a primary key constraint?

A: SQL Server normally rejects the entire multi-row INSERT statement.

Q: What is the difference between manual inserts and production ingestion?

A: Manual INSERT statements are useful for small datasets and testing. Production pipelines typically use automated, monitored, and validated ingestion methods.

## Day 1 — Step 21: Primary Key Constraint Practical

### 1. Definition
A Primary Key is a relational database constraint that uniquely identifies every row in a table and prohibits NULL key values.

### 2. Simple Meaning
Primary Key prevents two records from using the same key value.

### 3. Syntax

```sql
CREATE TABLE dbo.customers (
    customer_id INT NOT NULL PRIMARY KEY,
    customer_name NVARCHAR(100) NOT NULL,
    city NVARCHAR(100) NULL
);
```

### 4. Key Rules
- Primary Key values must be unique.
- Primary Key values cannot be NULL.
- A table has one primary key constraint.
- A primary key may contain multiple columns (composite primary key).

### 5. Why Use It?
To protect database integrity and reliably identify records.

### 6. Real Data Engineering Use
Data engineers validate customer and order identifiers during source ingestion and transformation. Relational database primary key constraints provide an additional layer of protection.

### 7. Duplicate Key Test

```sql
INSERT INTO dbo.customers
    (customer_id, customer_name, city)
VALUES
    (102, N'TEST', N'HYDERABAD');
GO
```

Expected: Primary Key violation, because customer ID 102 already exists.

### 8. Differences and Cautions
- PRIMARY KEY ensures uniqueness and non-NULL key values.
- NOT NULL only prevents NULL values.
- UNIQUE also enforces uniqueness, but NULL handling differs.
- Raw CSV and JSON files do not enforce SQL Server primary keys.
- Duplicate key errors should be investigated rather than bypassed.
- Never disable production constraints simply to force invalid data into a table.

### 9. Interview Q&A

**Q1. Can a primary key contain duplicate values?**
A: No.

**Q2. Can a primary key contain NULL values?**
A: No.

**Q3. Can a table have a composite primary key?**
A: Yes, a primary key can include multiple columns.

**Q4. What is SQL Server error 2627?**
A: It commonly indicates a violation of a primary key or unique constraint.

**Q5. What should a Data Engineer do when duplicate customer IDs arrive?**
A: Investigate source data and business rules, identify the correct record, and apply approved validation or deduplication logic.

A: To detect potential missing or extra records and verify whether the load meets expected requirements.
